# 미리내 · PC 버전

**실제로 동작하는 쪽이다.** 마이크에서 raw PCM을 받아 WebSocket으로 서버에 보내고,
전사·채점·섭동 계산 결과를 그대로 받는다.

폰 버전(`../app-mobile`)은 최종 제품 형태를 보여주는 UI 전용이다. 목적이 다르다.

## 실행

```bash
# 1) 서버
cd ../server
.venv\Scripts\python ws_server.py --port 8765

# 2) 앱
npm install
npm run dev          # http://localhost:5174 자동 실행
```

localhost는 브라우저가 secure context로 취급하므로 **HTTPS도 인증서도 필요 없다.**
폰 버전에 필요했던 자체 서명 인증서 단계가 통째로 사라진다 —
시연 당일 실패 요인이 하나 줄어든다는 뜻이다.

## 화면

좌우 2단이다. 왼쪽에 조작·상태·로그, 오른쪽에 실시간 내용을 놓았다.
시연 중에 "지금 무슨 일이 일어나고 있는지"가 한 화면에 보여야 하기 때문이다.

**모드 1 — 보이스피싱 감지**

- 실시간 전사와 매칭된 표현 강조
- 8단계 게이지 · 위험도 바 (주의 45% / 위험 75% 눈금)
- **판정 지연 표시** — 발화 종료부터 채점까지 몇 초 걸렸는지. D08의 지표(목표 ≤1.5초)를
  눈으로 확인할 수 있게 넣었다
- 발동한 규칙(C1~C5 · P1~P3) 표시
- 위험 도달 시 개입 오버레이 + 음성

**모드 2 — 딥보이스 방지**

- 청크 진행 타일 (대기 / 전송 / 완료 / **스텝 감축**)
- 청크당 처리 시간 표시. 홉(1.0초)보다 느리면 경고한다 — 적체가 쌓인다는 뜻이다
- A/B 재생과 WAV 저장. 저장한 보호본은 `clone_test.py`에 바로 넣을 수 있다

**설정** — 실행 환경 점검, 서버 주소, 연결 테스트, 경고 음성 미리 듣기

## 알아둘 것

- **모드 2 실시간 처리는 CUDA GPU가 필요하다.** CPU에서는 2초 청크 200스텝이
  수십 초 걸려 청크가 계속 밀린다. 서버가 스텝을 자동 감축하고 앱이 그 사실을 표시하지만,
  방어 강도가 떨어진 상태다. 실제 시연은 RTX 3060 장비에서 할 것
- 모드 1은 CPU에서도 동작한다 (faster-whisper base · int8)
- 마이크 캡처는 MediaRecorder가 아니라 **AudioWorklet raw PCM**이다.
  이유는 `../app-mobile/README.md`에 적어 두었다 — 손실 압축이 섭동을 지운다

## 코드 공유

`src/lib/`의 `recorder.ts` · `ws.ts` · `tts.ts`는 폰 버전과 같은 파일에서 출발했다.
플랫폼 의존이 없어 그대로 쓴다. 두 앱을 독립 프로젝트로 두어
한쪽을 고쳐도 다른 쪽이 깨지지 않게 했다 — 대신 lib를 고칠 때는 양쪽을 함께 봐야 한다.
