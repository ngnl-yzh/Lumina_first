# 미리내 · 폰 버전 (UI)

**UI 전용이다.** 마이크도 서버도 쓰지 않고 정해진 시나리오를 재생한다.
인터넷 없이 폰에서 단독으로 돌아간다.

실제로 동작하는 것은 `../app-desktop`이다. 목적이 다르다.

| | 폰 (이 앱) | PC (`app-desktop`) |
|---|---|---|
| 목적 | 최종 제품 형태를 보여준다 | 실제로 돌려서 확인·시연한다 |
| 마이크 | 안 쓴다 | AudioWorklet raw PCM |
| 서버 | 필요 없다 | WebSocket 필수 |
| 데이터 | 대본 재생 (`src/lib/demo.ts`) | 진짜 전사·채점·섭동 |

UI 전용이지만 **폰에서 제대로 보이는 것은 진짜다.** 데스크톱 목업(폰 베젤·가짜 상태바)이
아니라 실기기 전체 뷰포트를 쓰고, 노치·홈바는 `safe-area-inset`으로 피한다.
홈 화면에 추가하면 전체화면으로 실행된다.

## 실행

```bash
npm install
npm run dev:https      # 폰에서 접속하려면 HTTPS가 필요하다
```

폰에서 `https://<노트북IP>:5173` 접속. 자체 서명 인증서라 경고가 뜨는데 계속 진행하면 된다.

빌드해서 정적 호스팅에 올리면 인증서 문제 없이 배포할 수 있다.

```bash
npm run build          # dist/ 를 아무 정적 호스팅에나 올린다
```

## 재생되는 시나리오

`src/lib/demo.ts`에 있다. D07 §04 시연 순서를 따라 기관사칭 A 경로로 전개한다.

```
S1 권위 확립  →  S2 연루 통보  →  S3 공포 조성  →  S4 고립 유도 → 개입
   0.19            0.34            0.52            0.75
```

점수는 서버 스코어러(`mirinae.mode1.scorer`)가 같은 문장에 대해 내는 값을 옮긴 것이다.
**UI만 보여주더라도 숫자는 실제 알고리즘과 어긋나면 안 된다.**

모드 2는 12초 녹음에 11개 청크가 전송→처리→완료로 바뀌는 흐름을 보여준다.

## MediaRecorder를 쓰지 않는 이유 (PC 버전 해당)

설계도(D08 §06 · D09 §5.1)는 `recorder.js`에 MediaRecorder API를 지정했다.
**이 파이프라인에서는 쓸 수 없다.**

**① 압축된 오디오가 나온다.** iOS Safari는 audio/mp4(AAC), Chrome은 WebM/Opus다.
모드 2는 overlap-add로 섭동을 샘플 단위 정렬해 합치므로 압축을 거치면 정렬이 깨진다.

**② 손실 압축이 섭동을 지운다.** 이쪽이 더 결정적이다.
코덱은 정확히 "안 들리는 성분"을 버리도록 설계되어 있는데, 우리 섭동이 바로 그 성분이다.
심리음향 마스킹 아래에 숨긴 신호와 심리음향 코덱은 **같은 원리로 만들어졌다.**

→ PC 버전은 AudioWorklet으로 raw Float32 PCM을 직접 받는다.
   **D08 §06과 D09 §5.1의 모듈표를 이에 맞춰 고쳐야 한다.**

## 모바일 전용이라 코드에 들어간 것들

| 항목 | 왜 |
|---|---|
| `primeSpeech()` (탭 전환 시) | iOS는 제스처 밖 `speak()`를 무시한다. 경고 순간에 소리가 안 나는 사고를 막는다 |
| `viewport-fit=cover` + safe-area | 노치·홈바 |
| `overscroll-behavior: none` | 당겨서 새로고침되면 화면이 통째로 날아간다 |
| 입력 `font-size: 16px` | 16px 미만이면 iOS가 포커스 시 확대한다 |
| 터치 타겟 44px · 큰 글씨 옵션 | 주 사용자가 고령층이다 |
| 탭 전환 시 언마운트 | 타이머가 계속 도는 것을 막는다 |

## 실기기 검증

**아직 폰에서 한 번도 돌려보지 않았다.** D07이 D1 항목으로 잡아둔 확인이다.
UI 전용이라 마이크 권한 문제는 없지만, 레이아웃과 safe-area는 실기기에서 봐야 한다.
